# SyncClipboard Mobile 的 iOS 适配计划

每个会话按[开发入口](ios-next.md)完成一个功能 PR。当前进度和下一项工作见[交接台账](ios-handoff.md)。

基线为 `origin/main` 的 `7887864`（v1.1.8），Expo SDK 55、React Native 0.83.2。iOS 的自动剪贴板同步只在主 App 从后台恢复时进行一次。读取手机和当前服务器的状态，只传播单边变化，两端都有变化时保留各自内容。用户也可在主 App 手动上传或复制，或从其他 App 的分享面板发送选中内容。用户切走或锁屏后，iOS 可以挂起进程，普通剪贴板应用无法持续采集其他 App 的复制内容，也无法保证在桌面端变化时立即改写手机剪贴板。[Apple 后台执行策略](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app) · [系统剪贴板](https://developer.apple.com/documentation/uikit/uipasteboard)

## 恢复前台时如何决定同步方向

开启自动同步且已选定服务器时，把一次真正的 `background → active` 作为触发点，中间可以经过 `inactive`。停留前台、配置刷新、切换页面、粘贴授权弹窗关闭都不再开启一轮。普通冷启动按初始化处理，下次真正恢复时才自动检查。手动上传、复制和系统分享仍由用户随时发起。

**“有变化”按相邻两次有效检查计算。** 为每个服务器分别保存上一次确认的本地内容指纹和远端内容指纹。将本次本地与上次本地比较，远端与上次远端比较。两端目前内容不同，本身不足以推断谁更新了。

| 手机相对上次 | 服务器相对上次 | 本轮动作                                                 |
| ------------ | -------------- | -------------------------------------------------------- |
| 未变         | 未变           | 保留双方内容。                                           |
| 已变         | 未变           | 手机 → 服务器，上传本轮取得的本地内容。                  |
| 未变         | 已变           | 服务器 → 手机，取回本轮观察到的远端内容并写入剪贴板。    |
| 已变         | 已变           | 保留双方内容。记录本轮观察到的两个指纹，供下次分别比较。 |

首次取得该服务器的两份可靠快照时，只建立基准，即使内容不同也不猜方向。若两边已能确认是同一内容，直接确认当前指纹即可省去传输。成功的单向同步要记录**传输后**两侧的指纹。图片在系统板中的表示可能与远端文件字节不同，应保留本地与协议两种身份。基准记录以服务器稳定 ID 区分，配置改指其他地址、账号或存储桶/前缀时重新建立，避免把另一份剪贴板当成当前服务器的上一版。

**冲突只影响这一轮。** 假设上次两端都是 X，恢复时手机为 A、服务器为 B，则保留 A/B。下一次仍为 A/B 就不传。如果只有手机又从 A 改为 C，就把 C 上传。用户也可以在冲突时明确选“上传本机”或“复制远端”。同一服务器的手动操作与自动检查串行，同一轮已确认的两端事实才可更新基准。通过分享扩展发送选中的网页或文件，只确认这次远端写入，保留下次恢复时比较两端的基准。分享的内容未必在手机剪贴板上。

**缺一侧可靠快照就跳过本轮。** 粘贴权限被拒、读取失败、离线和认证失败都属于未知。若 API 无法区分“真的为空”和“拒绝读取”，不要把空结果作为清空对端的指令。以上情况不写任何一端，不推进基准，也不在本次前台停留期间反复重试。首个里程碑支持文本，图片读写及身份验证通过后加入。File/Group 沿用下载、导出入口，不能记成已写入系统板。[Expo SDK 55 Clipboard](https://docs.expo.dev/versions/v55.0.0/sdk/clipboard/) · [本地剪贴板实现](../src/services/clipboard/LocalClipboard.ts)

## 用户在 iPhone 上会经历什么

| 场景                            | 用户看到的结果                                                                                                                                                                                                                                                                                                 |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 首次配置、切换服务器            | 普通启动和保存设置不会触发自动覆盖。该服务器尚无基准时，首次有效恢复只记下两端状态。手动上传、复制入口可立即使用。连接自建服务器时说明局域网权限。                                                                                                                                                             |
| 外部 App 复制 A，同时桌面发布 B | 恢复后保留手机 A 和远端 B。首页可展示本次取得的两个快照，以及“上传本机”“复制远端”两个操作。                                                                                                                                                                                                                    |
| 停留前台时桌面又发布 C          | 自动同步保留上次检查的快照。用户可主动刷新远端预览。下一次从后台恢复才再次自动作出方向判定。                                                                                                                                                                                                                   |
| 锁屏期间复制多次或桌面连续修改  | 恢复时比较能取得的最新内容。iOS 的变更计数不会还原之前的复制正文。WebDAV/S3 也只提供最新 profile。SyncClipboard Server 的远端历史可以单独补齐，不触发当前剪贴板的自动写回。[Apple 剪贴板变更计数](https://developer.apple.com/documentation/uikit/uipasteboard/changecount)                                    |
| 主动分享或传输中锁屏            | 系统分享只处理显式传入的项目。已持久化但尚未送达时显示“待上传”，成功后显示“已上传”。若将来支持后台文件传输，URLSession 只继续已发起的任务。用户手动强退会取消这些任务。[Apple 后台 URLSession](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background%28withidentifier%3A%29) |

自动检查在 iOS 16 及以上读取其他 App 的剪贴板时可能出现系统粘贴授权提示，系统粘贴按钮不能代替无手势的自动读取。用户选择手动上传时，可用 `ClipboardPasteButton` 直接消费系统交付的内容。若保留模板的 iOS 15.1 下限，手动入口可以使用输入框的系统粘贴菜单。只在同一可靠会话内，才可利用 `UIPasteboard.changeCount` 和已确认的本地指纹省去重复读取。计数在设备重启后会重置。[Apple UIPasteControl](https://developer.apple.com/documentation/uikit/uipastecontrol) · [Apple changeCount](https://developer.apple.com/documentation/uikit/uipasteboard/changecount)

## 现有代码需要改动的位置

1. **先使原生入口可加载。** `App.tsx`、日志和服务层静态导入 `native-util`，包顶层先执行 `requireNativeModule('NativeUtilModule')`。修正加载顺序后，仍需逐项补齐传输与图片读写。[模块入口](../modules/native-util/src/index.ts) · [应用入口](../index.ts)
2. **先取得两侧快照，再作一次决定。** `ClipboardMonitor.triggerCheck()` 会通知本地订阅者，`RemoteClipboardMonitor.fetchLatest()` 也会广播远端变化，继而可能下载、入库或写板。iOS 自动入口跳过这两条带副作用的监听路径。直接用固定服务器客户端的 `getClipboard(signal)` 取得 profile，并读一次本地快照。比较时使用内容类型和稳定哈希，旧版纯文本 profile 缺哈希时可由完整文本计算。首页缓存、采样时间、短文本预览都不能充当内容指纹。[本地监听](../src/services/clipboard/ClipboardMonitor.ts) · [远端读取](../src/services/sync/RemoteClipboardMonitor.ts) · [协议转换](../src/utils/clipboard/convert.ts)
3. **持久化两侧状态。** 现有 `SyncStateStorage` 只有一个全局上传哈希，`JustSetHash` 是进程内防回环标记。应把一对指纹作为一条记录一起保存。单向传输只有在远端确认发布或本地写入成功后才提交结果，超时、取消、部分附件完成均保留旧基准。若写入已成功但应用未记下结果，下次先核对实际状态，已相同就确认，避免重复上传。[同步存储](../src/storage/SyncStateStorage.ts) · [回环标记](../src/services/sync/JustSetHash.ts)
4. **一轮只执行一个方向。** 自动上传传入这轮取得的内容。自动接收传入这轮取得的远端 profile，附件下载完成后才写板。停用 `ClipboardChangedHandler` 的启动时间窗口、自动上传/复制回调及写完重启本地轮询的路径。隔离手动刷新和快捷入口，避免取上一次缓存或在权限拒绝后循环读取。[同步动作](../src/services/sync/ClipboardSyncActions.ts) · [变更处理](../src/services/sync/ClipboardChangedHandler.ts) · [快捷入口](../src/screens/QuickTileLoadingScreen.tsx)
5. **同一次恢复只启动一个任务。** 当前协调器在配置刷新时也会重放前台回调。iOS 应记住是否真的进入过后台，并合并同一轮 `active` 通知。系统弹窗引起的短暂 `inactive` 只恢复原操作。把服务器身份、客户端和本轮取消信号贯穿采样与写入，退后台或切服后丢弃旧结果。遇到可能耗时的附件操作，写板前核对本地变化标记。远端支持条件写时校验版本或 ETag。现有三个后端的共享接口未提供统一的条件写保证，快照之后的并发修改仍有竞态窗口。[协调器](../src/longRunningTask/LongRunningTaskCoordinator.ts) · [客户端路由](../src/services/client/ClientService.ts) · [后端接口](../src/api/clients/APIClient.ts)

| SyncClipboard Server | 恢复时 GET 一次 `/SyncClipboard.json`。方向判定后才按需发布或写板。独立验收历史更新，`RemoteProfileChanged` 不触发第二轮自动检查。 | 分别验证历史开、关两种路由。历史创建支持纯字段和带 `data` 附件。验证 409、版本冲突、软删除和游标。若切换服务器，要核对已有单一 `last_sync_time` 的归属，必要时重置或按服务器记录，以免从另一台服务器的时间点续拉。[客户端路由](../src/services/client/ClientService.ts) · [HTTP 协议](../src/api/clients/SyncClipboardClient.ts) · [历史同步](../src/services/history/HistorySyncService.ts) |

**跨端数据不能只测“上传成功”。** 当前从系统剪贴板读取超过 1000 个 JS 字符的文本时，保存完整文件并生成 200 字符预览。分享用的 `createContentFromText` 却总返回内联全文。应把“由已取得的正文构造内容”统一到现有长文本语义，测 1000/1001、换行、中文和 emoji。文件身份为 `SHA256(原始文件名 + "|" + 大写文件字节SHA256)`。Group 为按相对路径 UTF-8 字节序排序的目录/文件条目摘要。用相同文件不同名、同批中文名不同选择顺序、随机缓存路径做固定样本，让 iOS、Android 和桌面端分别生成及消费。[本地文本](../src/services/clipboard/LocalClipboard.ts) · [内容构造](../src/utils/clipboard/clipboardContentUtils.ts) · [协议哈希](../src/utils/hash.ts)

## 从其他 App 发送的实现

当前 `ShareReceiveScreen` 只取 `resolvedSharedPayloads[0]`，成功后清空全部。锁定的 expo-sharing 55.0.11 扩展模板用一个 UserDefaults 键存一批分享，部分文件按原名存到共享目录，遇同名会移除旧文件，然后尝试打开主 App。即使启用 `ios.enabled`，连续两次分享、多个附件和主 App 未启动仍缺可靠交付。Expo 也将这种拉起主 App 的入站方式标为实验性。[现有分享页](../src/screens/ShareReceiveScreen.tsx) · [锁定版扩展模板](https://unpkg.com/expo-sharing@55.0.11/plugin/template-files/ios/ShareIntoViewController.swift) · [Expo SDK 55 Sharing](https://docs.expo.dev/versions/v55.0.0/sdk/sharing/)

1. **接收与暂存。** 用 Swift Share Extension 接收 `NSExtensionItem` / `NSItemProvider`。对本次分享分配独立任务目录，在文件表示的回调返回前复制临时文件，保留所有选中项的原名、类型和顺序。所有项目就绪后原子发布清单。用户取消或复制中断时，主 App 看不到半份任务。主 App 继续独占现有 SQLite 历史写入。扩展只写 App Group 中的待处理任务。[Apple Share Extension](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Share.html) · [临时文件生命周期](https://developer.apple.com/documentation/foundation/nsitemprovider/loadfilerepresentation%28fortypeidentifier%3Acompletionhandler%3A%29) · [历史库写入方式](../src/storage/HistoryDatabase.ts)
2. **发送与恢复。** 清单记录用户选定的服务器 ID 和任务 ID。主 App 认领并在成功后确认，重启能重新发现未确认任务。目标已删除、凭据改变或远端已更新时给用户重试/重新选择的入口。若请求成功但回执丢失，先核对服务端记录或当前 profile。避免把旧分享再次发布、覆盖后来内容。预览、失败、待上传、已上传分别反馈。
3. **分享面板内立即发送。** 先做短文本或链接，用目标后端确认作为成功条件。扩展需要读取目标配置和凭据。主 App 现将配置序列化到自己的 AsyncStorage，扩展有独立容器。共享非敏感服务器描述，凭据用配置好的 Keychain access group，以任务持有的服务器身份读取。后续若要在用户关闭面板后继续发送大附件，扩展与主 App 用各自的后台 session 标识和共同的 `sharedContainerIdentifier`，从磁盘上传并由主 App 重接完成事件。当前 JS 队列的数组、Map、AbortController 和定时重试都只活在一个进程内。[配置存储](../src/storage/ConfigStorage.ts) · [传输队列](../src/services/history/HistoryTransferQueue.ts) · [Apple 扩展共享与后台传输](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionScenarios.html)
